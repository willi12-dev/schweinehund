# REQ-001 – Datentest: Läufe per Teilen übernehmen
| | |
|---|---|
| **Status** | geplant |
| **Version** | v0.2.0 |
| **Grundlage** | zur Bestätigung vorgelegt 08.11.2026; Vorarbeit: Analyse echter Huawei-Exporte (GPX, TCX, Teilen-Bild) |

## Ziel
Nachweisen, dass Läufe von beiden Uhren-Welten ohne Zusatzkosten vollständig in
unsere App kommen – Zahlen und GPS-Strecke. Baut auf REQ-000 (Infrastruktur) auf; erst danach entsteht das Grundgerüst (REQ-002).

## Ablauf / Fachliches
1. **Testläufer A (Huawei):** Lauf in Huawei Health öffnen → Route exportieren →
   .gpx oder .tcx → Teilen → Schweinehund.
2. **Testläufer B (Garmin):** Zahlen kommen automatisch über Health Connect;
   zusätzlich ein Lauf als GPX/FIT per Teilen.
3. Die App erkennt den Lauf und zeigt eine Kontrollkarte
   („Lauf erkannt: 4,93 km, 1.6. 06:13 – speichern?“).
4. Übernommen werden die **Summen aus der Datei** (Distanz, Dauer, Anstieg);
   Kilometerzeiten werden aus den Punkten berechnet und auf die Summe skaliert.
5. Anstieg nur aus der Datei-Summe, nicht aus Einzelhöhen (Höhendrift beobachtet).
6. Bonus: Teilen-Bild (Screenshot) wird per Texterkennung gelesen
   (Puls, Kadenz, Schritte) und dem Lauf mit gleicher Startzeit zugeordnet.
7. Doppelte Läufe (gleiche Startzeit ± 2 Min.) werden erkannt und zusammengeführt.
8. Der Lauf geht an den TEST-Server; der Server bestätigt per Push.

## Bedienung und Technik
- App erscheint in der Android-Teilen-Leiste für GPX, TCX, FIT und Bilder;
  nimmt auch Dateien ohne klaren Typ an und prüft den Inhalt selbst.
- Mehrere Dateien auf einmal teilbar.
- Seite „Meine Läufe“ (letzte 30 Tage) mit Karte und Herkunft (Datei / Health Connect / Bild).
- Technik: Kotlin Multiplatform (vorerst Android), Karte MapLibre + OpenStreetMap,
  Texterkennung auf dem Gerät, Server Flask + SQLite auf PythonAnywhere (TEST),
  Push über Firebase.
- Verteilung: GitHub Actions baut die APK; Installation per Datei.
- Secrets (nur Namen): `PA_USERNAME`, `PA_API_TOKEN`, `PA_HOST`, `FIREBASE_KONTO`.

## Abnahme
- Regeltests mit den echten Beispieldateien (anonymisiert, Start/Ziel verschoben):
  · GPX-Leser: 2.584 Punkte, 4.970 m, 43:07, Anstieg 95,3 m
  · TCX-Leser: 2.411 Punkte, 4.930 m, 42:12, Anstieg 72,0 m
  · Kilometerzeiten skaliert: Abweichung zum Uhr-Wert ≤ 10 s je km
  · Bilderkennung: Dauer, Puls, Kadenz, Schritte, Datum korrekt
  · Doppelerkennung, Server-Empfang, Push-Auslösung
- Praxistest: je ein echter Lauf von A und B; Werte = Uhr; Lauf ≤ 1 Min. nach dem Teilen in der App.
- Ergebnisbericht `docs/analyse/datentest.md` mit Empfehlung für REQ-002.
